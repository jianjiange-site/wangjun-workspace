# 阶段 9：跨切片联调和交付检查

## 1. 阶段目标

完成 MVP 交付前的端到端联调和发布前检查：串联三条登录路径、JWT 验签、退出、refresh token、REST/gRPC 转换、BFF 聚合、Redis key 前缀、Nacos 配置、Docker、本地打包、日志脱敏、指标和 P95 / P99 压测准备。

本阶段不新增核心业务能力，只做跨切片验收和交付收口。

## 2. 阶段类型

联调验收。

## 3. 输入依据

- 最终方案第 23、24、25、26 章可靠性、兜底、可观测性和本地部署。
- 最终方案第 27 章 MVP 范围。
- 阶段 1-8 的交付物。

## 4. 输出结果

- `mvn -B -ntp clean package` 通过。
- 本地 Docker / docker compose 启动说明。
- 端到端联调脚本或 Postman / curl 集合。
- gRPC mock / grpcurl 验证说明。
- Redis key 前缀和 TTL 检查清单。
- P95 / P99 指标采集和压测脚本。
- 发布前风险清单。

## 5. 前置依赖

- 阶段 1-8 全部完成。

## 6. 耦合度说明

- 耦合度等级：高耦合。
- 耦合度总分：8。
- 排序理由：本阶段横跨 DB、Redis、gRPC、JWT、登录、BFF、Docker 和指标，但不新增业务逻辑，适合作为交付前收口。

## 7. 数据库低耦合说明

本阶段不新增表。只验证 migration 可在空库执行、历史 migration 不被修改、认证核心表字段和索引符合最终方案。

## 10. 详细任务拆分

### 任务 9.1：全量构建和测试收口

- 任务编号：9.1
- 任务名称：全量构建和测试收口
- 所属阶段：阶段 9
- 阶段类型：联调验收
- 业务闭环：所有 MVP 切片在同一工程内可构建、可测试。
- 涉及文件：Maven、全部测试。
- 作用：防止阶段间集成后出现编译和回归问题。
- 前置条件：阶段 1-8。
- 被阻塞于：阶段 1-8。
- 是否阻塞后续：是。
- 耦合度说明：跨全部模块。
- 数据库变更：验证 migration。
- API / gRPC / MQ 契约：验证 proto 生成。
- 实现要点：执行 `mvn -B -ntp clean package`；失败必须修复。
- 事务 / 幂等 / 一致性：验证 refresh token 并发、设备快登幂等。
- 异常和权限：验证业务码一致。
- 验收标准：全量测试和打包通过。
- 验证方式：命令行。
- 是否 MVP 必做：是。
- 建议执行方式：人工执行，AI 辅助修复。

### 任务 9.2：端到端认证链路联调

- 任务编号：9.2
- 任务名称：端到端认证链路联调
- 所属阶段：阶段 9
- 阶段类型：联调验收
- 业务闭环：三条登录路径、refresh、logout、受保护接口、BFF 可串联验证。
- 涉及文件：curl / Postman / mock 配置。
- 作用：确认用户真实路径可用。
- 前置条件：任务 9.1。
- 被阻塞于：任务 9.1。
- 是否阻塞后续：是。
- 耦合度说明：依赖多个接口和中间件。
- 数据库变更：验证账号、设备、refresh token 状态。
- API / gRPC / MQ 契约：验证所有 MVP REST 和代表性 gRPC。
- 实现要点：编写可重复执行的联调脚本，包含成功路径和失败路径。
- 事务 / 幂等 / 一致性：验证同设备同 `user_id`、refresh 只能成功一次、logout 幂等。
- 异常和权限：验证 `105XX`、`10600`、`107XX`、`108XX`。
- 验收标准：设备、手机、Google 登录均返回 token；refresh 成功；logout 后 token 被拒绝；BFF 返回可裁剪数据。
- 验证方式：curl / Postman / grpcurl / 数据库状态。
- 是否 MVP 必做：是。
- 建议执行方式：人工执行，AI 辅助生成脚本。

### 任务 9.3：配置、Nacos、Redis key 和 Docker 检查

- 任务编号：9.3
- 任务名称：配置、Nacos、Redis key 和 Docker 检查
- 所属阶段：阶段 9
- 阶段类型：联调验收
- 业务闭环：服务能以部署形态启动，并读取正确配置。
- 涉及文件：`application.yml`、`Dockerfile`、`docker-compose.yml`、runbook。
- 作用：降低部署环境风险。
- 前置条件：任务 9.1。
- 被阻塞于：任务 9.1。
- 是否阻塞后续：是。
- 耦合度说明：依赖配置中心、Redis、PostgreSQL。
- 数据库变更：验证 migration 自动或手动执行流程。
- API / gRPC / MQ 契约：验证 Nacos 服务发现。
- 实现要点：生产 Redis 前缀来自 Nacos `gateway.redis.key-prefix`；本地默认 `dating:mobile-gateway`；MVP 只部署一个生成 ID 的网关实例。
- 事务 / 幂等 / 一致性：部署检查避免多个固定 worker-id 实例同时生成 ID。
- 异常和权限：JWT 密钥缺失时服务不应健康。
- 验收标准：容器启动成功；Redis key 全部带统一前缀和 TTL；密钥缺失时启动失败或健康检查失败。
- 验证方式：本地 Docker、Redis CLI、日志。
- 是否 MVP 必做：是。
- 建议执行方式：人工执行。

### 任务 9.4：可观测性和日志脱敏检查

- 任务编号：9.4
- 任务名称：可观测性和日志脱敏检查
- 所属阶段：阶段 9
- 阶段类型：联调验收
- 业务闭环：请求、错误、下游耗时和敏感信息处理可观察、可排查。
- 涉及文件：日志配置、metrics。
- 作用：满足生产排障基本要求。
- 前置条件：任务 9.2。
- 被阻塞于：任务 9.2。
- 是否阻塞后续：是。
- 耦合度说明：跨全部入口和下游调用。
- 数据库变更：无。
- API / gRPC / MQ 契约：无。
- 实现要点：日志字段包括 traceId、path、method、user_id、account_id、device_id、downstream_service、cost_ms、error_code。
- 事务 / 幂等 / 一致性：无。
- 异常和权限：禁止打印 JWT、refresh token、验证码、手机号、Google token、设备原始 ID、密钥。
- 验收标准：成功和失败请求都有 traceId；敏感信息不出现在日志；指标包含 JWT、验证码、Google、设备登录、refresh、限流、gRPC、BFF、DB、Redis。
- 验证方式：日志断言、指标接口或采集系统检查。
- 是否 MVP 必做：是。
- 建议执行方式：人工检查，AI 辅助脚本。

### 任务 9.5：P95 / P99 压测准备

- 任务编号：9.5
- 任务名称：P95 / P99 压测准备
- 所属阶段：阶段 9
- 阶段类型：联调验收
- 业务闭环：关键接口可以输出 P95 / P99 和依赖池状态。
- 涉及文件：压测脚本、runbook。
- 作用：为上线容量判断提供依据。
- 前置条件：任务 9.2、9.4。
- 被阻塞于：任务 9.2、9.4。
- 是否阻塞后续：否。
- 耦合度说明：依赖完整环境和指标采集。
- 数据库变更：无。
- API / gRPC / MQ 契约：压测设备登录、refresh、受保护 REST、BFF。
- 实现要点：记录 P50 / P95 / P99、错误率、DB 连接池、Redis 连接池、gRPC channel 状态。
- 事务 / 幂等 / 一致性：压测数据使用隔离前缀或测试账号，避免污染真实环境。
- 异常和权限：压测不打印敏感 token。
- 验收标准：能输出各接口 P95 / P99；能观察 DB / Redis / gRPC 状态；目标值待业务规模确认。
- 验证方式：压测脚本。
- 是否 MVP 必做：是。
- 建议执行方式：人工执行，AI 辅助生成脚本。

## 11. 执行顺序

1. 全量测试和打包。
2. 端到端认证链路联调。
3. 配置、Nacos、Redis key 和 Docker 检查。
4. 可观测性和日志脱敏检查。
5. P95 / P99 压测准备。

## 12. 验收标准

- `mvn -B -ntp clean package` 通过。
- 设备、手机、Google 三条登录路径均通过。
- refresh token 轮换、重复使用检测、logout blacklist 均通过。
- REST/gRPC 转换和 BFF 首页接口均通过。
- Redis key 全部带 `gateway.redis.key-prefix` 配置前缀且有 TTL。
- JWT 私钥 / 公钥缺失时服务不健康。
- 日志无敏感明文。
- P50 / P95 / P99、错误率、DB / Redis / gRPC 指标可观察。

## 13. 默认假设 / 待确认事项

- P95 / P99 目标值仍待业务规模确认，本阶段先保证指标可采集和脚本可执行。
- 生产 CORS 白名单在部署前由环境配置确认。
