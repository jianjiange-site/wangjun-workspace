# 阶段 3：JWT 验签与退出黑名单闭环

## 1. 阶段目标

完成 access token 验签、认证上下文注入和退出 blacklist 闭环：业务请求携带 Bearer token 后，网关校验 RS256 签名、issuer、exp、typ、alg 和 Redis blacklist；退出时撤销当前会话并把 access token jti 写入 Redis blacklist。

## 2. 阶段类型

中耦合纵向切片。

## 3. 输入依据

- 最终方案第 16.2 章 `/api/v1/auth/logout`。
- 最终方案第 17.4 章 JWT 验签。
- 最终方案第 20、21 章幂等和安全。
- 最终方案第 22、23 章业务码和可靠性。

## 4. 输出结果

- `JwtAuthFilter` 完整实现。
- 认证上下文对象，包含 `user_id`、`account_id`、`device_id`、`trace_id`。
- `/api/v1/auth/logout` 接口。
- Redis blacklist key：`{redis_prefix}:jwt:blacklist:{jti}`。
- Redis blacklist 不可用时 fail closed，返回 `10508`。

## 5. 前置依赖

- 阶段 2：设备快速登录最小闭环。

## 6. 耦合度说明

- 耦合度等级：中耦合。
- 耦合度总分：5。
- 排序理由：依赖阶段 2 生成的 token 和 Redis blacklist，但主要在网关内部完成；它是后续 REST/gRPC 和 BFF 的鉴权前置。

## 7. 数据库低耦合说明

本阶段不新增表。退出时可按当前 refresh token / 会话信息撤销 `gateway_refresh_token`，access token blacklist 只写 Redis，不建 PostgreSQL blacklist 表。

## 10. 详细任务拆分

### 任务 3.1：JWT 验签和错误码映射

- 任务编号：3.1
- 任务名称：JWT 验签和错误码映射
- 所属阶段：阶段 3
- 阶段类型：中耦合纵向切片
- 业务闭环：携带有效 access token 的请求通过，非法 token 被拒绝。
- 涉及文件：`JwtService.java`、`JwtAuthFilter.java`
- 作用：保护所有非公开业务接口。
- 前置条件：阶段 2。
- 被阻塞于：阶段 2。
- 是否阻塞后续：是。
- 耦合度说明：依赖 JWT 公钥和阶段 2 的 token claim。
- 数据库变更：无。
- API / gRPC / MQ 契约：HTTP Authorization Bearer token。
- 实现要点：固定 RS256；MVP 不使用 `kid`；校验 issuer、exp、typ、alg；拒绝 `alg=none` 和错误公钥。
- 事务 / 幂等 / 一致性：无。
- 异常和权限：无 token 返回 `10100`；无效 token `10500`；过期 token `10501`。
- 验收标准：有效 token 通过；过期 token、错误 alg、错误 issuer、错误签名均被拒绝并映射正确业务码。
- 验证方式：Filter 单元测试。
- 是否 MVP 必做：是。
- 建议执行方式：人工实现核心安全逻辑，AI 辅助测试。

### 任务 3.2：认证上下文注入和透传准备

- 任务编号：3.2
- 任务名称：认证上下文注入和透传准备
- 所属阶段：阶段 3
- 阶段类型：中耦合纵向切片
- 业务闭环：鉴权通过后，下游业务能读取 `user_id`、`account_id`、`device_id`、`trace_id`。
- 涉及文件：`AuthContext.java`、`AuthContextHolder.java`、`JwtAuthFilter.java`
- 作用：为 REST/gRPC metadata 和 BFF 聚合提供认证上下文。
- 前置条件：任务 3.1。
- 被阻塞于：任务 3.1。
- 是否阻塞后续：是。
- 耦合度说明：本服务内部上下文能力。
- 数据库变更：无。
- API / gRPC / MQ 契约：后续 gRPC metadata 使用 `trace_id`、`user_id`、`account_id`、`device_id`。
- 实现要点：请求结束必须清理上下文，避免虚拟线程 / 线程复用场景污染。
- 事务 / 幂等 / 一致性：无。
- 异常和权限：上下文缺失时业务接口按未登录处理。
- 验收标准：请求内可读取上下文；请求结束后上下文清理；并发请求上下文不串。
- 验证方式：Web 并发测试。
- 是否 MVP 必做：是。
- 建议执行方式：AI 辅助修改。

### 任务 3.3：退出接口和 Redis blacklist

- 任务编号：3.3
- 任务名称：退出接口和 Redis blacklist
- 所属阶段：阶段 3
- 阶段类型：中耦合纵向切片
- 业务闭环：用户退出后，当前 access token 在剩余 TTL 内不能继续访问业务接口。
- 涉及文件：`AuthController.java`、`AuthService.java`、`RedisKeyFactory.java`
- 作用：完成 `/api/v1/auth/logout`。
- 前置条件：任务 3.1、3.2。
- 被阻塞于：任务 3.1、3.2。
- 是否阻塞后续：否。
- 耦合度说明：依赖 Redis 和当前 token jti。
- 数据库变更：可将当前 refresh token 会话标记为 REVOKED；不建 access token blacklist 表。
- API / gRPC / MQ 契约：`POST /api/v1/auth/logout` 需要鉴权。
- 实现要点：Redis blacklist TTL 等于 access token 剩余 TTL；logout 重复调用返回成功或已退出，不抛系统异常。
- 事务 / 幂等 / 一致性：refresh token 撤销是本地事务；blacklist 写失败时不声明退出成功。
- 异常和权限：blacklist 命中返回 `10502`。
- 验收标准：登录后调用 logout 返回成功；再次使用同 access token 调业务接口返回 `10502`；Redis key 带统一前缀和 TTL。
- 验证方式：HTTP + Redis 集成测试。
- 是否 MVP 必做：是。
- 建议执行方式：AI 辅助修改。

- 任务编号：3.4

- 阶段类型：中耦合纵向切片
- 业务闭环：Redis blacklist 不可用时拒绝业务请求，日志不泄漏 token。
- 涉及文件：`JwtAuthFilter.java`、日志配置、异常处理。
- 作用：落实 Redis-only blacklist 的可靠性边界。
- 前置条件：任务 3.3。
- 被阻塞于：任务 3.3。
- 是否阻塞后续：是。
- 耦合度说明：依赖 Redis 异常路径。
- 数据库变更：无。
- API / gRPC / MQ 契约：无。
- 实现要点：blacklist Redis 异常返回 `10508`；限流 Redis 异常与 blacklist Redis 异常分开处理。
- 事务 / 幂等 / 一致性：无。
- 异常和权限：返回 `10508`；禁止日志打印 JWT 明文。
- 验收标准：模拟 Redis blacklist 查询失败时返回 `10508`；日志中不包含 access token、refresh token、密钥。
- 验证方式：异常注入测试、日志断言。
- 是否 MVP 必做：是。
- 建议执行方式：AI 辅助修改。

## 12. 验收标准

- 有效 access token 可访问受保护接口。
- 缺失 token 返回 `10100`。
- 无效 token 返回 `10500`，过期 token 返回 `10501`。
- logout 后同 access token 被 Redis blacklist 拒绝，返回 `10502`。
- Redis blacklist 查询不可用时返回 `10508`。
- 日志不打印 JWT、refresh token、验证码、手机号、Google token、设备原始 ID 和密钥。
