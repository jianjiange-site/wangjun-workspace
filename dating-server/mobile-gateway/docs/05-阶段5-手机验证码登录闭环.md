# 阶段 5：手机验证码登录闭环

## 1. 阶段目标

完成手机号验证码登录 / 注册闭环：发送验证码时写 Redis 验证码 hash 和冷却 key；登录时校验手机号、验证码、限流，使用 `PHONE + phone_hash` 查找或创建账号，调用 user-service 初始化，成功后签发 access token 和 refresh token。

## 2. 阶段类型

中耦合纵向切片。

## 3. 输入依据

- 最终方案第 13 章 Redis 缓存设计。
- 最终方案第 16.2 章认证接口。
- 最终方案第 17.1 章手机验证码登录 / 注册。
- 最终方案第 21、22、23 章安全、业务码和可靠性。

## 4. 输出结果

- `/api/v1/auth/sms-code` 发送验证码接口。
- `/api/v1/auth/login/phone` 手机验证码登录接口。
- Redis `sms-code`、`sms-cooldown`、`login-fail` key。
- `SmsProviderClient` 抽象和 Mock 实现。
- PHONE 类型账号创建 / 登录，复用 user-service 初始化和 token 签发能力。

## 5. 前置依赖

- 阶段 2：设备快速登录最小闭环。
- 阶段 3：JWT 验签与退出黑名单闭环。

## 6. 耦合度说明

- 耦合度等级：中耦合。
- 耦合度总分：6。
- 排序理由：复用阶段 2 的账号和 token 能力，新增 Redis 验证码和短信供应商适配；供应商可 mock，因此不阻塞主闭环。

## 7. 数据库低耦合说明

本阶段不新增表。手机号原文不落库，使用 `PHONE + phone_hash` 写入 `gateway_account.account_type` 和 `account_key_hash`。

## 10. 详细任务拆分

### 任务 5.1：验证码发送和冷却

- 任务编号：5.1
- 任务名称：验证码发送和冷却
- 所属阶段：阶段 5
- 阶段类型：中耦合纵向切片
- 业务闭环：客户端请求发送验证码后，Redis 保存验证码 hash，并限制频繁发送。
- 涉及文件：`SmsCodeService.java`、`SmsProviderClient.java`
- 作用：提供手机登录前置凭据。
- 前置条件：阶段 1、阶段 2。
- 被阻塞于：阶段 1、阶段 2。
- 是否阻塞后续：是。
- 耦合度说明：依赖 Redis 和短信供应商 mock。
- 数据库变更：无。
- API / gRPC / MQ 契约：`POST /api/v1/auth/sms-code`。
- 实现要点：手机号格式校验；手机号 HMAC 后作为 Redis key；验证码只保存 hash；冷却 TTL 60s。
- 事务 / 幂等 / 一致性：无数据库事务。
- 异常和权限：发送过于频繁返回 `10201`，参数错误返回 `10001`。
- 验收标准：合法手机号发送后 Redis 存在验证码 hash 和冷却 key；重复发送返回 `10201`。
- 验证方式：HTTP + Redis 集成测试。
- 是否 MVP 必做：是。
- 建议执行方式：AI 辅助修改。

### 任务 5.2：验证码校验和失败计数

- 任务编号：5.2
- 任务名称：验证码校验和失败计数
- 所属阶段：阶段 5
- 阶段类型：中耦合纵向切片
- 业务闭环：登录时只接受有效验证码，成功后立即删除验证码。
- 涉及文件：`SmsCodeService.java`、`RedisKeyFactory.java`
- 作用：防止验证码重放和暴力尝试。
- 前置条件：任务 5.1。
- 被阻塞于：任务 5.1。
- 是否阻塞后续：是。
- 耦合度说明：依赖 Redis。
- 数据库变更：无。
- API / gRPC / MQ 契约：`POST /api/v1/auth/login/phone`。
- 实现要点：校验失败增加 `login-fail:PHONE:{phone_hash}`；校验成功删除 `sms-code`。
- 事务 / 幂等 / 一致性：验证码成功消费后不可再次使用。
- 异常和权限：验证码无效或过期返回 `10200`，校验过于频繁返回 `10202`，Redis 不可用 fail closed。
- 验收标准：错误验证码返回 `10200`；正确验证码成功后 Redis 验证码 key 被删除；同验证码不能二次登录。
- 验证方式：Redis 集成测试。
- 是否 MVP 必做：是。
- 建议执行方式：AI 辅助修改。

- 所属阶段：阶段 5
- 阶段类型：中耦合纵向切片
- 业务闭环：手机号验证码通过后，创建或查询 PHONE 账号并签发 token。
- 涉及文件：`AuthService.java`、`GatewayAccountManager.java`、DTO / VO。
- 作用：完成手机号登录 / 注册。
- 前置条件：任务 5.2、阶段 2。
- 被阻塞于：任务 5.2、阶段 2。
- 是否阻塞后续：否。

## 11. 执行顺序

1. 实现验证码发送和冷却。
2. 实现验证码校验、删除和失败计数。
3. 实现 PHONE 账号登录 / 注册。
4. 补齐异常、Redis 不可用和日志脱敏测试。

## 12. 验收标准

- `POST /api/v1/auth/sms-code` 合法请求后 Redis 存在验证码 hash，TTL 约 5 分钟。
- 60 秒内重复发送返回 `10201`。
- 错误验证码返回 `10200`。
- 正确验证码登录成功后删除验证码 key。
- 首次手机号登录创建 `account_type=PHONE` 的账号并返回 token。
- 再次同手机号登录复用同一个 `user_id`。
- 日志不出现手机号和验证码明文。
