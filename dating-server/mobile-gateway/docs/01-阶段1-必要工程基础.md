# 阶段 1：必要工程基础

## 1. 阶段目标

完成 `mobile-gateway` 最小可运行工程基础：Spring Boot MVC + JDK 21 虚拟线程、统一返回、数值型业务码、全局异常、Nacos 配置绑定、Redis key 前缀、traceId、CORS、基础限流、雪花 ID、HMAC 工具、gRPC 契约骨架和本地测试框架。

本阶段不实现完整登录业务，但要让后续所有认证、转发、BFF 切片可以复用统一基础设施。

## 2. 阶段类型

必要前置。

## 3. 输入依据

- 最终方案第 4 章团队技术约束。
- 最终方案第 10 章技术选型。
- 最终方案第 11 章项目结构。
- 最终方案第 13 章 Redis key 前缀。
- 最终方案第 16.1 章统一返回。
- 最终方案第 22 章业务码。
- 最终方案第 25、26 章可观测性和本地配置。

## 4. 输出结果

- 可启动的 `mobile-gateway` Spring Boot MVC 工程。
- 虚拟线程开启：`spring.threads.virtual.enabled=true`。
- 统一 `Result<T>`、业务码枚举、全局异常处理。
- `TraceIdFilter`、`CorsConfig`、`RateLimitService` 基础能力。
- Nacos / 本地配置绑定，包含 `gateway.redis.key-prefix`，默认 `dating:mobile-gateway`。
- `RedisKeyFactory` 统一拼接 Redis key，禁止业务代码硬编码前缀。
- 雪花 ID 生成器，MVP 固定 `worker-id=1`、`datacenter-id=1`。
- HMAC 工具，支持手机号、Google subject、设备号、refresh token 分别使用不同 secret。
- user-service `RegisterOrInitialize` proto / client mock 骨架。

## 5. 前置依赖

无。

## 10. 详细任务拆分

### 任务 1.1：工程骨架和虚拟线程启动

- 任务编号：1.1
- 任务名称：工程骨架和虚拟线程启动
- 所属阶段：阶段 1
- 阶段类型：必要前置
- 业务闭环：提供后续业务切片可运行的 Spring Boot MVC 基础。
- 涉及文件：`pom.xml`、`MobileGatewayApplication.java`、`application.yml`、`VirtualThreadConfig.java`
- 作用：统一依赖版本、启动入口、虚拟线程、MVC 基础配置。
- 前置条件：无。
- 被阻塞于：无。
- 是否阻塞后续：是。
- 耦合度说明：不依赖外部服务，仅依赖本地启动环境。
- 数据库变更：无。
- API / gRPC / MQ 契约：无。
- 实现要点：使用 Spring Boot 3.3.5、JDK 21、Maven；禁止 WebFlux；开启 `spring.threads.virtual.enabled=true`。
- 事务 / 幂等 / 一致性：无。
- 异常和权限：启动失败应清晰暴露缺失配置。
- 验收标准：`mvn -B -ntp test` 通过；应用可本地启动；启动日志显示虚拟线程配置生效。
- 验证方式：单元测试、本地启动。
- 是否 MVP 必做：是。
- 建议执行方式：AI 生成初稿，人工检查依赖版本。

### 任务 1.2：统一返回、业务码和异常处理

- 任务编号：1.2
- 任务名称：统一返回、业务码和异常处理
- 所属阶段：阶段 1
- 阶段类型：必要前置
- 业务闭环：所有 REST 接口都返回统一结构和数值型业务码。
- 涉及文件：`Result.java`、`ResultCode.java`、`BusinessException.java`、`GlobalExceptionHandler.java`
- 作用：统一 `code/message/data/traceId`，并登记 `10000-10899` 网关业务码。
- 前置条件：任务 1.1。
- 被阻塞于：任务 1.1。
- 是否阻塞后续：是。
- 耦合度说明：仅本服务内部公共能力。
- 数据库变更：无。
- API / gRPC / MQ 契约：REST 返回固定为 `{code,message,data,traceId}`。
- 实现要点：业务码使用整数；`105XX` 专用于 Token / JWT / refresh token / blacklist；禁止字符串业务码。
- 事务 / 幂等 / 一致性：无。
- 异常和权限：参数错误返回 `10001`，系统异常返回 `10000`，未登录返回 `10100`。
- 验收标准：模拟 Controller 抛出 `BusinessException` 时返回对应业务码；未知异常不泄漏堆栈和敏感配置。
- 验证方式：WebMvcTest。
- 是否 MVP 必做：是。
- 建议执行方式：AI 生成初稿。

### 任务 1.3：配置绑定、Redis key 前缀和 HMAC / ID 工具

- 任务编号：1.3
- 任务名称：配置绑定、Redis key 前缀和 HMAC / ID 工具
- 所属阶段：阶段 1
- 阶段类型：必要前置
- 业务闭环：后续登录切片可安全生成业务 ID、hash 标识和 Redis key。
- 涉及文件：`GatewayProperties.java`、`RedisKeyFactory.java`、`SnowflakeIdGenerator.java`、`HmacHasher.java`
- 作用：统一读取 Nacos / 本地配置，避免 Redis 前缀、worker-id 和 secret 散落在业务代码。
- 前置条件：任务 1.1。
- 被阻塞于：任务 1.1。
- 是否阻塞后续：是。
- 耦合度说明：依赖配置，不依赖真实业务数据。
- 数据库变更：无。
- API / gRPC / MQ 契约：无。
- 实现要点：`gateway.redis.key-prefix` 默认 `dating:mobile-gateway`；MVP 固定 `worker-id=1`、`datacenter-id=1`；HMAC 输出固定格式并带 `hash_version`。
- 事务 / 幂等 / 一致性：雪花 ID 生成必须在单实例下不重复。
- 异常和权限：JWT 私钥、公钥、HMAC secret 缺失时启动失败或健康检查失败。
- 验收标准：同一输入 HMAC 结果稳定；不同 secret 结果不同；Redis key 全部带前缀；连续生成 10 万个 ID 不重复且非 0。
- 验证方式：单元测试。
- 是否 MVP 必做：是。
- 建议执行方式：AI 生成初稿，人工检查密钥处理。

### 任务 1.4：traceId、CORS、限流基础

- 任务编号：1.4
- 任务名称：traceId、CORS、限流基础
- 所属阶段：阶段 1
- 阶段类型：必要前置
- 业务闭环：所有入口请求具备 traceId，可按配置进行跨域和基础限流。
- 涉及文件：`TraceIdFilter.java`、`CorsConfig.java`、`RateLimitFilter.java`、`RateLimitService.java`
- 作用：为登录接口、业务转发和 BFF 统一入口控制。
- 前置条件：任务 1.2、1.3。
- 被阻塞于：任务 1.2、1.3。
- 是否阻塞后续：是。
- 耦合度说明：依赖 Redis 用于限流，traceId / CORS 可独立验证。
- 数据库变更：无。
- API / gRPC / MQ 契约：HTTP response header 返回 traceId；gRPC metadata 透传由后续阶段使用。
- 实现要点：限流 key 使用 `RedisKeyFactory`；Redis 限流异常按接口风险配置 fail open / fail closed；登录公开接口必须限流。
- 事务 / 幂等 / 一致性：无。
- 异常和权限：触发限流返回 `10600`。
- 验收标准：请求无 traceId 时生成并返回；请求带 traceId 时透传；超过阈值返回 `10600`；预检 CORS 请求按配置返回。
- 验证方式：Web 集成测试、Redis mock / Testcontainers。
- 是否 MVP 必做：是。
- 建议执行方式：AI 辅助修改。

### 任务 1.5：user-service gRPC 契约骨架

- 任务编号：1.5
- 任务名称：user-service gRPC 契约骨架
- 所属阶段：阶段 1
- 阶段类型：必要前置
- 业务闭环：后续首次注册可以调用 user-service 初始化，不形成跨服务事务。
- 涉及文件：`src/main/proto/user_register.proto`、`UserGrpcClient.java`、`GrpcClientConfig.java`
- 作用：定义 `RegisterOrInitialize` 调用入口、deadline、metadata 和 mock。
- 前置条件：任务 1.1、1.2。
- 被阻塞于：任务 1.1、1.2。
- 是否阻塞后续：是。
- 耦合度说明：依赖一个外部服务契约，但可用 mock 独立验收。
- 数据库变更：无。
- API / gRPC / MQ 契约：`user_id:int64`、`account_type:string`、`register_source:string`、`trace_id:string`；返回成功 / 失败状态。
- 实现要点：gRPC 必须设置 deadline；metadata 预留 `trace_id`；user-service 以 `user_id` 幂等。
- 事务 / 幂等 / 一致性：禁止在本地事务内调用 gRPC。
- 异常和权限：超时映射为 `10701`，异常映射为 `10702`，初始化失败映射为 `10703`。
- 验收标准：mock user-service 返回成功时 client 解析成功；超时时映射 `10701`；异常时映射 `10702`。
- 验证方式：gRPC mock 测试。
- 是否 MVP 必做：是。
- 建议执行方式：AI 生成初稿。

## 12. 验收标准

- `mvn -B -ntp test` 通过。
- 应用本地启动成功，端口和应用名符合配置。
- `Result<T>` 固定包含 `code`、`message`、`data`、`traceId`。
- 业务码为整数，且覆盖 `10000-10899` 网关码段。
- Redis key 生成结果包含 Nacos / 本地配置的 `gateway.redis.key-prefix`。
- traceId 可生成、透传并写入日志上下文。
- CORS 配置可通过集成测试验证。
- 限流命中返回 `10600`。
- user-service gRPC mock 可验证成功、超时和异常映射。
