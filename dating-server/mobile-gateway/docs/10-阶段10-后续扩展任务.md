# 阶段 10：后续扩展任务

## 1. 阶段目标

记录明确不属于 MVP 的后续能力，避免它们混入当前开发主线造成过度设计。只有当 MVP 已完成并出现真实业务需求时，才进入本阶段任务。

## 2. 阶段类型

后续扩展。

## 3. 输入依据

- 最终方案第 27.2 章明确不做范围。
- 最终方案第 27.3 章后续扩展。
- 用户已确认的 MVP 取舍。

## 4. 输出结果

- 非 MVP 能力列表。
- 每项扩展的前置条件和风险。
- 后续单独立项建议。

## 5. 前置依赖

- 阶段 9：跨切片联调和交付检查。

## 6. 耦合度说明

- 耦合度等级：高风险聚合。
- 耦合度总分：12。
- 排序理由：扩展任务通常涉及多个登录方式、多实例部署、安全密钥、审计、后台或更多第三方平台，容易改变服务边界和数据模型，必须后置。

## 7. 数据库低耦合说明

本阶段不在 MVP 中新增表。涉及登录审计、账号绑定、密钥轮换、多实例 worker-id 时，应单独设计表结构和 migration，不修改历史 migration。

## 10. 详细任务拆分

### 任务 10.1：账号绑定、合并和设备升级

- 任务编号：10.1
- 任务名称：账号绑定、合并和设备升级
- 所属阶段：阶段 10
- 阶段类型：后续扩展
- 业务闭环：允许手机号、Google、设备账号之间建立绑定或合并关系。
- 涉及文件：待单独设计。
- 作用：解决多登录方式身份统一。
- 前置条件：MVP 登录稳定运行，有真实账号合并需求。
- 被阻塞于：阶段 9。
- 是否阻塞后续：否。
- 耦合度说明：涉及现有账号模型、用户资料、风控和冲突处理，风险高。
- 数据库变更：可能新增账号绑定表、合并记录表。
- API / gRPC / MQ 契约：可能需要 user-service 配合。
- 实现要点：必须先定义合并规则、冲突处理、回滚策略和审计。
- 事务 / 幂等 / 一致性：可能涉及跨服务一致性，需单独设计。
- 异常和权限：敏感操作需要更高安全要求。
- 验收标准：需新方案评审后确定。
- 验证方式：单独设计。
- 是否 MVP 必做：否。
- 建议执行方式：后续扩展。

### 任务 10.2：Apple / 微信等第三方登录

- 任务编号：10.2
- 任务名称：Apple / 微信等第三方登录
- 所属阶段：阶段 10
- 阶段类型：后续扩展
- 业务闭环：接入更多第三方身份提供方。
- 涉及文件：待单独设计。
- 作用：扩大登录渠道。
- 前置条件：Google 登录模式稳定。
- 被阻塞于：阶段 6、阶段 9。
- 是否阻塞后续：否。
- 耦合度说明：每个第三方协议、密钥、回调和错误码不同。
- 数据库变更：复用 `gateway_account` 或扩展字段需评审。
- API / gRPC / MQ 契约：第三方平台接口。
- 实现要点：按 provider 抽象 token 校验，不污染 Google 逻辑。
- 事务 / 幂等 / 一致性：复用账号唯一键。
- 异常和权限：第三方 token 不落日志。
- 验收标准：按具体平台定义。
- 验证方式：第三方 sandbox 联调。
- 是否 MVP 必做：否。
- 建议执行方式：后续扩展。

### 任务 10.3：登录审计表

- 任务编号：10.3
- 任务名称：登录审计表
- 所属阶段：阶段 10
- 阶段类型：后续扩展
- 业务闭环：记录登录、刷新、退出、失败尝试等审计事件。
- 涉及文件：migration、审计 service。
- 作用：支持安全排查和风控。
- 前置条件：MVP 登录链路稳定。
- 被阻塞于：阶段 9。
- 是否阻塞后续：否。
- 耦合度说明：中耦合，可能影响所有认证入口。
- 数据库变更：新增登录审计表。
- API / gRPC / MQ 契约：无或异步事件，需单独设计。
- 实现要点：避免在主交易链路中过度增加延迟。
- 事务 / 幂等 / 一致性：审计失败不能破坏主登录流程，除非安全策略另行定义。
- 异常和权限：审计内容必须脱敏。
- 验收标准：单独设计。
- 验证方式：DB 查询和日志验证。
- 是否 MVP 必做：否。
- 建议执行方式：后续扩展。

### 任务 10.4：JWT kid 和多密钥轮换

- 任务编号：10.4
- 任务名称：JWT kid 和多密钥轮换
- 所属阶段：阶段 10
- 阶段类型：后续扩展
- 业务闭环：支持多个签名密钥并在线轮换。
- 涉及文件：`JwtService`、配置、密钥管理。
- 作用：提升密钥治理能力。
- 前置条件：MVP 单密钥稳定运行。
- 被阻塞于：阶段 9。
- 是否阻塞后续：否。
- 耦合度说明：高耦合，影响签发、验签、回滚和监控。
- 数据库变更：可能新增密钥配置表或依赖配置中心。
- API / gRPC / MQ 契约：JWT header 增加 `kid`。
- 实现要点：必须设计新旧密钥并行、回滚窗口、过期策略和审计。
- 事务 / 幂等 / 一致性：密钥切换要保证旧 token 在 TTL 内可验。
- 异常和权限：密钥泄漏风险高。
- 验收标准：单独安全评审。
- 验证方式：安全测试、回滚演练。
- 是否 MVP 必做：否。
- 建议执行方式：后续扩展。

### 任务 10.5：多实例 worker-id 分配

- 任务编号：10.5
- 任务名称：多实例 worker-id 分配
- 所属阶段：阶段 10
- 阶段类型：后续扩展
- 业务闭环：支持多个 `mobile-gateway` 实例安全生成雪花 ID。
- 涉及文件：ID 生成配置、启动检查。
- 作用：支持横向扩容。
- 前置条件：存在多实例部署需求。
- 被阻塞于：阶段 9。
- 是否阻塞后续：否。
- 耦合度说明：高耦合，错误会造成全局 ID 冲突。
- 数据库变更：可能需要 worker 分配表或依赖 Nacos / Redis 锁，需单独评审。
- API / gRPC / MQ 契约：无。
- 实现要点：设计 worker-id 分配、租约、冲突检测、启动失败策略。
- 事务 / 幂等 / 一致性：必须保证同一时间没有两个实例使用同一个 worker-id。
- 异常和权限：冲突时服务必须拒绝启动或停止生成 ID。
- 验收标准：多实例并发生成 ID 无冲突。
- 验证方式：并发和故障注入测试。
- 是否 MVP 必做：否。
- 建议执行方式：后续扩展。

### 任务 10.6：管理后台和运维接口

- 任务编号：10.6
- 任务名称：管理后台和运维接口
- 所属阶段：阶段 10
- 阶段类型：后续扩展
- 业务闭环：提供账号禁用、会话撤销、配置查看等运营能力。
- 涉及文件：待单独设计。
- 作用：支持运营和安全处置。
- 前置条件：有明确运营角色、权限模型和审计要求。
- 被阻塞于：阶段 9。
- 是否阻塞后续：否。
- 耦合度说明：高耦合，涉及安全权限和审计。
- 数据库变更：可能新增审计、操作记录、角色权限表。
- API / gRPC / MQ 契约：后台 API。
- 实现要点：不能混入公网网关主路径；必须有强鉴权和审计。
- 事务 / 幂等 / 一致性：按具体操作设计。
- 异常和权限：后台权限错误风险高。
- 验收标准：单独设计。
- 验证方式：权限和审计测试。
- 是否 MVP 必做：否。
- 建议执行方式：后续扩展。

## 11. 执行顺序

1. 先基于真实业务需求选择一个扩展方向。
2. 重新做需求澄清和技术方案评审。
3. 明确是否改变服务边界和数据归属。
4. 再按纵向切片重新拆分。

## 12. 验收标准

- 本阶段不作为 MVP 验收条件。
- 每个扩展项必须有独立需求、方案、评审和验收标准。
- 扩展项不得破坏 MVP 已有登录、JWT、refresh、REST/gRPC 和 BFF 行为。

## 13. 默认假设 / 待确认事项

- 当前版本不做账号绑定、登录审计、`kid`、多实例 worker-id、管理后台和运维接口。
- 后续任何扩展都必须保持业务编号使用 `xxx_id`。
